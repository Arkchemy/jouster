TWO ANSWERS
-----------
this=0 and vt=0. These are not vtables with holes in them, which was the
leading guess -- they are virtual calls on a NULL object. That distinction
matters because the two need completely different fixes, which is why the
probe was built to tell them apart.

Those are the same problem. Nothing downstream is asking for more classes
because the objects being built are incomplete.

THE SITE
--------
A loop in Core::igMetaObject::createInstanceInPlace:

    2160d3c: add   r28, r12, r6     ; start of the field array
    2160d40: add   r30, r12, r10    ; end
    2160d4c: lwz   r3,  0(r28)      ; array[i]          <- NULL
    2160d50: lwz   r12, 0(r3)       ; its vtable
    2160d54: lwz   r6,  0x124(r12)
    2160d60: bctrl                  ; virtual method on the field
    2160d64: addi  r28, r28, 4

It walks a metaobject's field array calling one virtual method per entry. A
null entry means that field was never instantiated, so the object is
constructed without its fields.

WHY THE PREVIOUS PROBES COULD NOT SAY THIS
-------------------------------------------
pc reported 0x214d258, which is igMetaField::construct -- a function whose
entire body is a single blr. lr reported the return address inside the loop.
Neither could distinguish a null object from a null slot, because
g_ppc_current_pc names the innermost function ENTERED and nothing restores it
when a leaf returns. Recording r3 and its first word settled it in one run.

THIS BUILD (23:17)
------------------
createInstanceInPlace's own `this` is the metaobject, held in r29, and a
metaobject's name pointer is at +0x8 -- the same offset the registration log
already reads. So the class can be named rather than inferred:

    nullfield: hits=%u meta=0x%x n=%u nulls=%u name="%s"

  nulls == n   -> the whole field array is empty, so field allocation never
                  ran for this class
  nulls < n    -> some fields exist and some do not, which points at per-field
                  construction rather than allocation
  name         -> the class to look at next
