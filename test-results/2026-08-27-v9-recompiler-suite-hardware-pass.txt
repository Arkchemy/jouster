Arkchemy @ commit 986866a (2026-08-27), native/Arkchemy.nro, run on real

9/9 PASS, 0 failures.

This is the first hardware run since the org split, and the first for
which the generated C was regenerated rather than inherited: t1-t5 are
no longer the 2026-08-14 build's output. They came out identical anyway,
which is the useful part -- the recompiler changes since then (the
per-translation-unit ppc_run_static_initializers, the ~240 lines of
ppc_runtime.h this repo had been pinned behind) did not move any of the
five previously-passing answers, and blaster's build_ppc.sh switch to
powerpc-freestanding-eabihf did not move t2_floating's FP result.

t6-t9 are new to hardware. All four cover things found in real code
rather than invented for a test: andi./lwzu, conditional return and
addis/frsp came out of recompiling a genuine Wii U homebrew .rpx, and
bss_large is the oversized-.bss address-assignment bug from the real
Skylanders binary. t8_addis_frsp is the one that would have silently
stopped testing anything under a newer zig -- soft float removes the
frsp instruction entirely -- so its PASS here is specifically a
hard-float result.

The figure scan and NFC read are not pass/fail checks and are not
counted: no dumps were placed in sdmc:/switch/Jouster/figures and no
figure was placed on the controller during this run, so "no dumps found"
and "no figure detected in time" are the expected outcomes, not
failures.

Coverage note, recorded because it is the obvious next question: this
suite ran 9 of the 23 test programs blaster's verify.sh runs under
QEMU. The remaining 14 (bitops, rotate, carry, division, indexed, fcmp,
mulhw, double, misc_bitops, mixed_double, globals, multifunc_globals,
manyargs, multifile) were added to the suite immediately after this run
and need their own hardware pass.
