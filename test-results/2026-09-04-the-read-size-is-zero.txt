THE ARITHMETIC -- igArchive::addWork, 0x216aa9c
  r10 = [fileWorkItem+0x14]   offset
  r7  = [fileWorkItem+0x18]   size
  r4  = r10 >> 15                    -> workItem+0x14   first block
  r6  = (r10 + r7 - 1) >> 15         -> workItem+0x18   last block
  blocks = (r6 - r4) + 1
  (Block size 0x8000. An earlier grep missed this shift because it is `srwi`,
  not `srawi`.)

  Ours reads +0x14=1, +0x18=0. Those two expressions can produce that pair
  only when size == 0, with offset exactly 0x8000: then r8 = 0x7fff and
  r8>>15 = 0 while r10>>15 = 1. Block count comes out (0-1)+1 = 0.
  Retail reads +0x14=1, +0x18=33, which implies a size of about 1 MB.

  So the read length is zero. Everything downstream follows from that: no
  blocks to issue, nothing to drain, updateTasks skipping every pass.
