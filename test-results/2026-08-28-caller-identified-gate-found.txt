So the object is created one instruction before it is used, and it is an
igMemoryPoolHandlePool -- a SUBCLASS of igHandlePool. _handleList is a
base-class field.

  igMemoryPoolHandlePool::instantiateFromPool
    21c64a8: bl getClassMetaSafeInternal(&metaSlot, arkRegisterInternal)
    21c64b4: bl igMetaObject::createInstance(pool)

That is the lazy get-or-register chain, and this project already
documented it. From findings.json, "The lazy metaobject registration
chain, and the single flag byte that gates it":

  "...calls igArkCore::beginArkRegister, which reads a flag byte at
   offset +0x16 on the igArkCore singleton; only if the flag passes does
   it invoke the class's own arkRegisterInitialize... If reflection
   appears to be missing wholesale rather than for one class, that byte
   is the thing to look at first."

beginArkRegister confirms it exactly:

  2154d74: lbz   r0, 0x16(r3)     flag
  2154d78: cmpwi r0, 0
  2154d7c: beq   0x2154d8c        flag == 0 -> do nothing
  2154d80: lwz   r12, 0x18(r3)    otherwise depth++
  2154d8c: mr    r3, r0           returns the flag

It has been measured firing 23 times, but the hit count says nothing
about the RETURN VALUE, and the return value is what decides whether a
class registers. That distinction was never measured.

A fourth probe now reports the igArkCore pointer, the flag byte, the
nesting depth and the caller, on every one of those 23 calls.
