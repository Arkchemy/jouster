    registry @frame  600: table=0x4405388 populated=796 highest=2047 index540=empty

THE ANSWER
----------
Index 540 is never filled. The table ends up with 799 populated entries
scattered across indices reaching 2047, so it is genuinely SPARSE, and 540 is
a hole rather than a slot registration had not yet reached. Ordering alone
does not explain it.

HONEST LIMIT ON THAT CONCLUSION
--------------------------------
`populated` freezes at 799 from frame 900 onward because the game thread hangs
there. Registration stops because of the hang, and the hang is caused by the
missing entry. So strictly: index 540 is not registered by the time it is
needed, and nothing after the hang can fill it. Whether a healthy boot would
have registered it later cannot be settled from inside a run that stops. What
IS settled is that entries far beyond 540 (up to 2047) are already present
when 540 is still empty, which is not what a purely sequential shortfall looks
like.
