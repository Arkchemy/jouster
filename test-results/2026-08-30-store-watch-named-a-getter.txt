THE SAME MISTAKE, SEVENTH TIME
------------------------------
The store watch recorded g_ppc_current_pc, which is set at function ENTRY and
never restored on return. For a store made by code that is not a recompiled
function -- a Cafe OS shim, a memory helper calling ppc_store_u32 directly --
it names whatever ran last rather than the writer.

The same correction was already made to the dispatch-miss probe hours earlier,
and this instrument was left with the old behaviour. Previous victims of it:
_main, _savegpr_14_l, igMetaField::construct, a field-array loop, grow, and a
one-off null object. That is enough repetitions to treat it as a property of
the instrument rather than a series of accidents.

FIXED IN conquertron
--------------------
ppc_store_u32's watch now records ctx->lr as well, under debug-watch id
0xf0000020 -- 0xf0000007 was already taken by control_bytevalue in the harness
and would have reported the lr under another watch's name.
