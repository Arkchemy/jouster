AN INSTRUMENTATION GAP I INTRODUCED
-----------------------------------
The store watch reported hits=0 while the value demonstrably changed. Both
writes are stwcx., and yesterday's atomics fix routes atomic stores through
ppc_stwcx, which did not report to the store watches at all. Before that fix
every guest write went through ppc_store_u32, which does.

So every "never written" store-watch result since 2026-09-03 17:36 is
unreliable for any atomically-updated address. That includes two conclusions
in this log: "flag A is written once at init and never again" and "the
task's _decompressJobFlag is untouched". Both were about lock-free counters,
which is exactly the category the gap hides.

Fixed: ppc_stwcx now reports to both store watches the same way a plain
store does. Those two conclusions should be re-measured before being relied
on.

The build that first carried the fix failed to compile -- the watch globals
are declared below the atomics block -- and the failure left the previous
binary in Jouster.nro, which was queued for push. Cleared before it went,
forward declarations added, rebuilt clean.
