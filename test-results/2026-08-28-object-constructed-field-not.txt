THE OBJECT IS FINE. ONE FIELD IS NOT.

The vtable word is a real pointer (0x11f0b0), so this is a properly
constructed igObject rather than raw zeroed memory. _freeHandle, the
scalar field, holds 0xffff -- a sensible "none" sentinel, so
initialisation ran and did something deliberate.

_handleList, the one OBJECT-typed field, is null. It is an igDataList
that something has to allocate and attach.

So the fault is not allocation, not construction, not registration, and
not the recompiler's dispatch. It is specifically the instantiation of a
reflected object-typed field.

WHY THIS MATTERS BEYOND THIS ONE FIELD

If object-typed metafields are not being instantiated in general, then
every engine class with an object-typed member is in the same state, and
this single null is the first one that happened to be dereferenced. That
would explain the shape of the whole boot failure far better than any of
the registration theories it replaced.
