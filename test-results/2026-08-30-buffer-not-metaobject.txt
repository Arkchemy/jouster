THE INSTRUCTION
---------------

    2160dc8: oris r0, r0, 8      ; |= 0x80000
    2160dcc: stw  r0, 4(r31)

flag write on the newly constructed object, and it is correct code.

r31 is `mem`, the element buffer, and it is 0x34D4 = .data+5332. Setting a
flag four bytes into a static-data address lands on the memory-context pointer
at .data+5336.

was correct: r3 is the METAOBJECT and it is a healthy heap pointer,

argument is r4, the buffer.

Two inferences in a row went to the wrong argument -- first the metaobject via
the +0x18 refcount, then the metaobject again via the probe. Recording the
registers ended it in one run, and is the reason the store watch now does that
by default.
