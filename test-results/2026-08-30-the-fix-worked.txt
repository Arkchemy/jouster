-------------------------------------------------------
distinct=114, blocked=113. Both callers walk the table, but one initializer

THE NEW FAILURE, WHICH IS A REAL ONE
------------------------------------
Hard hang at frame ~3480: calls frozen at 204,131, all twenty tail samples at
last_pc=0x25834a8 with caller_lr=0x21d9b00 -- __gh_memclr32 called from
Core::igJobQueue::init.

It is NOT in memclr32. That call is `li r4, 0x606` / `bl 0x25834a8`, so 1,542
words, 192 iterations of the unrolled loop, and the translation is faithful
(rlwinm to r4>>3, bdnz decrementing, stwu updating). It cannot spin.

The reason it LOOKS like memclr32 is a gap in the harness. A Cafe OS shim is
not a recompiled function: it sets no g_ppc_current_pc and increments no
g_ppc_fn_call_count. So a loop built from shims and inline code advances no
counter at all, and looks exactly like a hang inside the last recompiled
function entered. igJobQueue::init calls OSGetCurrentThread twice within a few
instructions of that memclr, and a job queue that starts workers and waits for
them is precisely the shape that spins when the wait is a shim.
